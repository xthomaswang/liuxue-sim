# 第二版玩法：抽天赋、会变的学期、更少的字

日期：2026-10-12。来源是用户试玩第一版后的反馈，以及用户点名的两个参考：《人生重开模拟器》（开局十连抽天赋、选三个）和《大学模拟器》（每学期的“学期规划”可选项会变、有随机事件）。

用户的原话要点：折叠的文字太多，不需要这么多字；保持简洁和简单的选项，文字描述在上方、下面就是选项；每学期有点固化，要加随机性和随机事件，时间可以按学期走，但事件不要每局完全一样；家庭之类的选择都做成开局抽出来的。

本文与 `01`/`02`/`03`/`06`/`13` 冲突时以本文为准；没有提到的规则不变（四属性与截断、申请抽档与三校 offer、支线分配、毕业资格与概率公式、硕士续篇、`07` 结局文案、`14` 结局卡）。规则版本提升到 `2.0.0`，旧存档判为版本不符。

## 1. 开局：出身是抽的，天赋十连抽选三

开局只有一屏，玩家只做一件事：从十张天赋里选三张。没有姓名输入，没有家庭三选一，没有愿望选择。

### 1.1 出身（抽出来，不能选）

```text
economy:      r = draw01(seed, "origin:economy");  r < 0.30 → LOW；r < 0.75 → MID；否则 HIGH
expectation:  [ACADEMIC, STABILITY, AUTONOMY][pickIndex(seed, "origin:expectation", 3)]
aspiration:   [DISCOVERY, INDEPENDENCE, BELONGING][pickIndex(seed, "origin:aspiration", 3)]
```

经济档的初始资金、每学期资助仍按 `03` 第 2.1 节。期待与愿望仍然只影响结局文案（以及 `14` 的 H07）。

### 1.2 天赋

天赋池在 `17_TALENTS.md`。每张有稀有度 `N / R / SR / SSR`，抽取权重分别为 `100 / 45 / 15 / 4`。

十连抽是按权重的无放回抽样，池内顺序即文档数组顺序：

```text
remaining = 全部天赋
for i in 0..9:
    r = draw01(seed, "talent:draw:" + i) * sum(weight(t) for t in remaining)
    依次累加 remaining 的权重，取第一张累计值严格大于 r 的；浮点极端情况取最后一张
    从 remaining 移除
```

玩家必须恰好选 3 张、互不相同、都来自这十张。确认后不可更换。想换一批只能重新开局（新 seed），不提供原地重抽。

### 1.3 天赋效果

效果是数据，引擎只认下面这些键。三张天赋的同类效果相加；唯一的例外是 `efficiencyFloor`，取其中最大的一个：

| 键 | 含义 | 作用位置 |
|---|---|---|
| `initial` | 开局四属性的增减 | 经济档初始值加上三张天赋的 `initial` 之和，再截断到 0–100 |
| `stipend` | 每学期资助的增减 | 发放资助时，结果不低于 0 |
| `upkeep` | 每学期必要开销的增减 | 期末结算与硕士预算，结果不低于 0 |
| `focus` | 按类别给学期安排的四属性加成 | 加到所选安排的向量上，先加成、再算身心效率 |
| `focusWellbeingRelief` | 安排带来的负身心少扣 N | `min(0, 身心变化 + N)` |
| `readiness` | 申请准备度加成 | `readiness = clamp(base + HS_01 加成 + 天赋加成, 0, 100)` |
| `chance` | 某一路毕业机会的概率加成（百分点） | 整数公式里给 `n` 加 `100 × 加成`，再四舍五入并截断到 8–上限；不改变资格 |
| `efficiencyFloor` | 身心效率的下限（8 或 10） | 取 `max(按身心算出的效率, 下限)` |
| `arcWeight` | 某条支线的分配权重加成 | 支线加权分配 |
| `growth` | 每学期基础变化的增减 | 期末的基础成长 |

第一版的六种特质变成六张固定天赋，效果与 `03` 第 2.3 节逐项相同（OUTGOING 的友情支线权重 +2、REFLECTIVE 的创作支线权重 +1 也算在内）：`T_FOCUSED`、`T_PRACTICAL`、`T_OUTGOING`、`T_FRUGAL`、`T_RESILIENT`、`T_REFLECTIVE`。

天赋里可以有带代价的（负面或有得有失），玩家可以不选。天赋不改变资格规则，不新增状态条。

## 2. 学期安排：每学期四个，每次不一样

原来每学期固定五个投入选项，现在每学期从安排池（`18_TERM_PLANS.md`）里给出四个。

- 每张安排属于五个类别之一（`STUDY / CAREER / CAMPUS / WORK / REST`），有自己的名字和四属性向量。投入次数仍按类别累计，毕业资格与概率公式照旧。
- **每学期缺一个类别**：

  ```text
  allowed = [STUDY, CAREER, CAMPUS, WORK, REST] 去掉上一学期缺的那个类别（该学段第 1 学期不去掉）
  missing = allowed[pickIndex(seed, "plan:missing:" + stage + ":" + term, allowed.length)]
  ```

  所以同一个类别不会连续两个学期都缺。
- **其余四个类别各出一张**：

  ```text
  candidates = 该类别的全部安排（池内顺序），去掉上一学期这个类别出过的那张（候选不足 2 张时不去掉）
  plan = candidates[pickIndex(seed, "plan:pick:" + stage + ":" + term + ":" + category, candidates.length)]
  ```

  展示顺序固定为 STUDY、CAREER、CAMPUS、WORK、REST 中出现的那四个。
- 安排是否出现只取决于 seed 和学期，与玩家之前的选择无关。
- 结算：取安排的向量，加上天赋的类别加成与负身心减免，按选择前的身心算效率（只折减正的学业／职业，半入），应用并截断。安排要花钱而资金不足时不可选并写明差额。
- 内容约束保证不会卡死：只有 `CAMPUS` 与 `REST` 类别允许有花钱的安排，其余三类一律不花钱，所以任何学期至少有两个不花钱的选项。
- 五张“基础安排”（id 就是类别名，向量与 `03` 第 3 节的表逐项相同）也在池里。

## 3. 事件：主线槽每局不同

每学期仍然是一张主线槽事件；本科第 2–7 学期另有一幕支线（支线规则不变）。

- **第 1、8 学期**（抵达与告别）：从这个节点的候选里等概率取一张。候选是原来的 `CORE_0n` 加上 `19_MAIN_EVENT_VARIANTS.md` 里同一节点的变体，按 id 排序：

  ```text
  event = candidates[pickIndex(seed, "event:main:" + term, candidates.length)]
  ```
- **第 2–7 学期**：先决定这学期是节点事件还是随机事件。

  ```text
  remaining = 随机事件池（20_RANDOM_EVENTS.md，池内顺序）里本局还没出现过的
  if draw01(seed, "event:kind:" + term) < 0.45 and remaining 非空:
      event = remaining[pickIndex(seed, "event:random:" + term, remaining.length)]
  else:
      event = 同上，从这个节点的候选里取
  ```
- 新事件与原事件同一套规则：两个选项、效果确定、唯一标记 `<事件ID>_<A|B>`、每张至少一个不花钱的选项、单项绝对值不超过 8、四项绝对值之和不超过 16。
- 回响（callbacks）照旧是条件触发；引用的事件这一局没出现，就不显示。
- 硕士学期的事件不变（`MASTER_01`–`04`）。

## 4. 突发小事

每学期开始、资助到账之后：

```text
if draw01(seed, "happening:roll:" + stage + ":" + term) < 0.60:
    pool = 突发小事池（21_HAPPENINGS.md，池内顺序）里适用于当前学段（scope 为 ANY 或当前学段）且本局没出现过的
    if pool 非空:
        happening = pool[pickIndex(seed, "happening:pick:" + stage + ":" + term, pool.length)]
        应用它的四属性变化（单独截断；资金不够扣时扣到 0，不产生债务），记一条 HAPPENING 历史
```

突发小事没有选项，只是一行字加数值变化，显示在这学期安排选择的上方。它不设置历史标记，不影响资格。

## 5. 学期流程：去掉学期小结这一步

一个学期现在是：`（资助到账 + 可能的突发小事）→ 选安排 → 主线槽事件 →（支线事件）`，然后直接进入下一学期。

- 没有 `TERM_REVIEW` 阶段，也没有“继续”按钮。学期最后一张事件的那次操作里依次完成：事件结算 → 必要开销与短缺 → 基础成长 → 若还有学期：学期数加一、发资助、抽突发小事，进入选安排；否则冻结毕业快照，进入毕业机会预览。
- 上学期的结算（必要开销、短缺压力、基础成长）作为一行账目显示在下一屏上方，不单独占一屏。
- 每一次属性变化仍然各自截断、各记一条历史。

## 6. 界面：上面是描述，下面是选项

- 游戏过程中的每一屏只有两部分：上方一小段描述，下方是选项按钮。
- **不再有可展开的长文**：事件长正文、长结果、家庭详情、概率分解都不显示。事件只显示标题与摘要，选后只显示短结果。
- 选项按钮只有名字和实际的四属性变化；不可选时写明原因；会导致期末资金短缺时给一个简短提醒。
- 上一步的结果、上学期的结算、这学期的资助和突发小事，各占一行小字，放在描述上方。
- 结局页：短结局正文、关键经历、状态、三路机会结果、结局卡、五年后一段、本局的三张天赋；“回看这次经历”只列出各节点的标题与当时的选择，不再逐条展开。
- 毕业机会页保留整数概率与“准备尚不足”时的资格条件，不显示概率分解。

## 7. 经典模式（只给测试用）

`createRun` 可以指定 `mode: "classic"`：不抽天赋与出身（由调用方给定经济档与恰好一张特质天赋）、每学期固定给出五张基础安排、主线槽固定用 `CORE_01`–`08`、没有突发小事。除了没有学期小结这一步，数值结果与第一版完全相同，用来继续和 `work/validate_design.py` 的 Python 参考实现逐学期对拍。界面不提供这个入口。

## 8. 结局相关的小调整

- `07` 第 8 节的历史回顾里，“本科 `CORE_01`、`CORE_04`、`CORE_08`”改为“本科第 1、4、8 学期主线槽里实际出现的那张事件”。条数不变。
- 结局页与完整回顾里加一行本局的三张天赋。
- `14` 结局卡的规则不变。出身现在是抽的，所以 `UR`（需要宽裕家庭）更看运气。

## 9. 验收

- 同 seed：出身、十张天赋、每学期的四个安排、主线槽事件、突发小事、三校 offer、支线、毕业抽签全部可复现；换选择不会让后面的抽取错位。
- 任意学期至少有两个不花钱的安排；任何资金局面都有可选的事件选项；没有会卡住的状态。
- 同一类别不会连续两学期缺席；同一张随机事件、同一条突发小事一局内不重复。
- 经典模式与 Python 参考实现逐学期一致。
- 用自动模拟检查：不同 seed 的两局，主线槽事件序列与安排序列相同的比例很低；四属性始终是 0–100 的整数。
- 默认界面没有任何展开链接（结局页的“回看这次经历”除外）。

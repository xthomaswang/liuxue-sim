# 高中最后一年：准备与申请

## 1. 位置与边界

家庭与个人愿望选择之后，玩家完成 `HS_01` 和 `HS_02` 两个事件，再进入大学申请结算。两件事件分别回答“怎样准备”和“怎样选择申请策略”，不扩展成一整个高中养成游戏。

四属性已经由家庭与个人特质初始化。每件高中事件只结算所选 `effects`，设置唯一历史标记；结果直接带入本科。高中阶段不选择投入重心，不发放学期资助，不结算学期费用，不推进支线，也不增加标准化考试、单独的高中成绩、文书等级或推荐信系统。

`academics` 在这一阶段表示学习基础与课程准备，`career` 表示作品实践、表达与协作的可迁移积累，并不表示高中生已经拥有正式职业。数值名称和 UI 标签保持统一，避免在入学时额外换算一套属性。

两次选择之后，申请算法读取 seed 确定的基础准备度与高中准备、策略标记，产生一个 offer 档次，再由全国学校目录在同档内不放回抽取三所大学。四属性的高中改动保留到本科，不重复计入申请准备度。玩家只能从这三所 offer 里选择。准确公式见 `13_ADMISSIONS_AND_TEMPO.md`；本文件不内嵌概率、不直接返回档次、不保证某所学校。

首版为纯文字界面。默认显示 `summary` 与最近一个匹配 callback 的 `shortText`，选择后显示 `shortResult`，不多加确认页。完整 `body/result` 与长回响可展开阅读。

## 2. 两种准备与两种策略

`HS_01_A` 注重课程基础与持续学习，`HS_01_B` 注重已有作品、实践和个人表达。两者都是合理准备，不能将 B 写成“成绩不好才去包装自己”，也不能保证 A 一定去更高档的学校。

`HS_02_A` 为冲刺策略，其 offer 档次分布更分散；`HS_02_B` 为稳健策略，分布更集中在中间档。这里描述的是游戏申请模型，实际分布由准备度与策略规则共同确定。冲刺不等于直接提高所有结果，稳健不等于保证录取某一档。玩家在确认策略前应能看到由系统计算的分档概率提示，但故事结果只说已按该策略准备递交，等到统一申请结算时才揭晓结果。

高中只需家人、老师和同学等泛称，不新增常驻人物。不指定某所真实中学、不编造真实老师，也不假定玩家来自某种固定学校体系。

## 4. 实现与验收

- `HS_01`、`HS_02` 各只出现一次，顺序固定；每件事件只有 A/B 两个选择。
- 四个历史标记固定为 `HS_01_A`、`HS_01_B`、`HS_02_A`、`HS_02_B`，每局只得到其中两个；申请公式从这些标记推导准备和策略，不重复存储同义布尔值。
- 事件不能在 `result` 中提前插入实际学校、预设档次或录取状态。申请结算只在 `HS_02` 效果落定后执行一次。
- 进入本科时保留高中后的四属性和历史标记，不重新初始化家庭资源或个人特质。毕业机会可以读取累计状态，但不另给未规定的高中奖励。
- 每个选项的数值单项绝对值不超过 8，四项绝对值之和不超过 16；两事件全部选项都不消耗资金，不会因家庭初始余额把玩家堵在开局。
- 家庭选择、两段高中、学校结果和大学主线之间无需额外演出或图片。保留足够快的推进方式，使包括最长硕士线的一局仍以 6–9 分钟为目标。

# 实施决策记录

记录编码阶段相对 00–13 设计包所做的决定与偏离，以及依据。日期均为 2026-10-11。发生冲突时，本文与 `14_ENDING_CARDS.md` 优先于更早的文档里被它们明确替换的条款；没有提到的条款仍以原文档为准。

## 1. 三种交付形态共用一套代码

用户要求同时提供网站、iOS app 和能在 Mac 上直接打开的版本。原设计只写了“桌面浏览器单页游戏”。

- 规则引擎（`src/engine`，纯函数）与界面（`src/ui`、`src/app`，React）只写一份，用 Vite 构建成静态站点 `dist/`。这就是**网站**形态。
- **iOS 与 macOS** 是 `apple/` 下一个 Xcode 工程：SwiftUI 外壳里放一个 `WKWebView`，通过自定义 URL scheme 从 app 包内加载同一份 `dist/`。外壳不含任何游戏逻辑。
- 不用 Capacitor / Tauri / Electron / xcodegen / CocoaPods：外壳只有几个 Swift 文件，手写工程即可，避免给机器装全局工具，也避免多一条依赖链。
- 不用 `file://` 加载：ES module 与 localStorage 在 `file://` 下不可靠；自定义 scheme 给了稳定的 origin，存档（localStorage）在 app 重启后仍在。
- 界面因此改为手机优先的单栏排版，并用 `env(safe-area-inset-*)` 适配刘海与圆角。

## 2. 学校范围缩小为精选目录

原 `11_SCHOOLS_AND_SOURCES.md` 要求导入全国 IPEDS 目录。用户在编码阶段决定缩小范围：只收 U.S. News 综合大学前 200 左右、最好的一批文理学院、少量其他特殊学院。

- 目录模式为 `CURATED`（精选），不是全国目录；不得对外称“覆盖全部美国大学”。
- 学校事实（UNITID、官方英文名、城市、州）仍然只从 IPEDS 目录按 UNITID 精确连接取得，不凭印象填写。`HD2025`/`IC2025` 在编码时实测为 404，原文档说“2025 可见”不成立，实际使用 **2024 年** 的 `HD2024`/`IC2024`（原始文件放在 `~/Developer/ml_source/datasets/ipeds/2024/`，不进仓库）。
- 分档有两种依据，逐校标注在数据里并在界面上区分：
  - `VERIFIED_2027`：有可机械复核的 2027 版排名证据（出版方新闻稿或学校官网），带具体名次。复核方式是脚本重新抓取来源页，规范化后的正文必须包含摘录的引文。
  - `APPROXIMATE`：没有逐校核实 2027 版名次，按近年榜单的大致区间放进档位，不写具体名次。这是为缩小范围而接受的折中，档位可能与 2027 版相差一档。
  - `UNRANKED_SPECIAL`：综合榜不排名的专门院校，进入 U 池。
- 因为范围只到 200 名左右，档位映射改为 v2（`usnews-2027-game-v2`）：综合大学 S 1–20／A 21–50／B 51–100／C 101–150／D 151 及以后；文理学院 S 1–10／A 11–25／B 26–50／C 51–100／D 101 及以后；地区性大学前 10 进 B（只收有已核实证据的少数几所）。原文档的 v1 把 D 定为 201 名以后，在新范围里 D 池会是空的。
- `13` 的申请机制不变：U 池固定 10%，其余 90% 按准备度与策略在 S–D 之间分配；每池至少 3 所才允许开局。U 现在的含义是“综合榜不排名的专门院校”，仍然不是最低档。
- 中文校名由模型整理、未经人工审核，数据里有标注；没有通行译名的学校显示官方英文名。

## 4. 状态、存档与防重复

- `RunState` 用 `SETUP` 与进行中两种形态的联合类型表示：开局阶段只有 seed 与版本，没有伪造的学校或属性占位。
- 每个操作带着发出时看到的 `revision`；引擎只接受与当前 `revision` 一致的操作，所以连点、重放、过期按钮都不会重复结算。
- 存档除了状态，还保存从开局到当前的全部操作。读档时（学校目录未变的情况下）从 seed 重放这些操作，结果必须与存档里的状态完全一致，否则判为损坏。这样损坏或被改动的存档不会被当成正常的一局继续玩。
- 学校目录更新后：已经抽出三所 offer 的存档继续可玩（学校记录已冻结在存档里），还没抽 offer 的存档明确提示需要重新开始。
- 申请结果在 `HS_02` 的选择里一并生成，没有单独的“揭晓”操作；界面可以分步展示，但不会多抽一次。
- 学期回顾是单独的一步（一个“继续”按钮），不与下一学期的投入选择合并。

## 5. 没有做、或尚待验证的事

- **真人试玩与十分钟计时**没有做，也无法由开发者代做。仓库里只有自动走完整局的测试与点击次数统计。
- **iOS 真机**：这台机器没有签名身份，只在模拟器上验证；装到真机需要在 Xcode 里选择自己的开发者 Team。
- **Mac app** 是本机 ad-hoc 签名，可以在本机直接打开；分发给别人需要正式签名与公证。
- 没有部署网站，也没有推送到任何远端。
